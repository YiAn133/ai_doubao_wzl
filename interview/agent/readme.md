# Agent 智能体 ？
字面意义上，AI自主干活。
这么理解没有问题，但是遮住了一个更重要的问题。

Agent和普通的AI对话，到底他的差别在哪里呢？
- 对话结构
普通AI：普通对话，一问一答就结束
案例：帮我写一份邮件
llm写完，任务就终止了。
回答机器，输出一次，没有后续。
Agent不一样，他有一个持续运转的结构。
你给他一个任务，他会去拆任务，决定下一步，去调工具，看结果。
这个过程是一个循环，直到任务完成，或者它自己判断（超出循环次数，token上线，相同结果次数，失败了）

### Agent工作方式，核心三个动作  
- 第一个动作 思考 Reason
- 第二个动作 行动 Act
- 第三个动作 观察 Observe
一轮的，观察后再回到思考，再行动，再观察，循环往复，这个循环，就叫ReAct
React(Reasoning + Act + Observe)是一套标准Agent 执行流程/Agent工作框架，不是LangChain那种大型开发库，是Agent通用的循环工作标准。

## demo
帮我分析的竞品，然后去写一份报告，Agent会怎么做。
- 第一轮思考
    需要去搜索竞品的信息
    调用搜索工具（act），去咨询三家竞品的最新动态
    查完以后，把结果拿回来。
    然后观察（observe）信息量挺大。
    到这里第一轮结束了，接着？

    再回到思考，发现缺少了财务数据（reason）
    可以去官网或股市API（Act）
    去抓取相应数据
    观察
    第三轮，第四轮....
    最后一轮，报告写完，交给我们。

Agent 最核心的动作，就是Tool Use
工具是Agent的手脚，没有工具，它只能在脑子里转。转完之后，还是只有文字。

- 常见工具：
- 搜索工具，能上网查询实时信息
- 代码执行器，能运行代码，能看结果。
- 文件读写I/O
- 浏览器的操控browser打开网页，点击提交，
- API 调用
工具越多，Agent能干的事情越多。
很多Agent产品，调用了很多工具，工具的覆盖范围，直接决定Agent的能力边界，选择Agent的核心
