# 轻松上手Vibe Coding

想要用AI写代码，但是AI生成的要不是“幻觉代码”，看起来像那么回事，但是一跑就错，要么就是屎山代码，能跑
但是乱的想改都不知道怎么下手。

- 这个指南，不是怎么写代码，而是叫我们去与AI协作写出靠谱的代码。

- 项目入手，不要急于写代码，先思考规划 md文件
    每次prompt 都会自动带上规划，保持一致性，有整体、的约束

## 操作的核心方法
- 第一步：规划就是一切。
不要上来就让AI写代码，先强制让它去读懂你的技术栈和项目规划。
就好像你不会让新来的员工直接干活一样，好比阿里入职，有java员工手册等
得让AI熟悉公司业务流程一样，这样AI生成的代码逻辑就清晰多了。

## demo
场景 用React + TailWind 实现一个任务清单（待办）页面

vibe 新兵：直接上手代码，极易幻觉，屎山。
老手：
    - 要不要本地存储
    - 要不要api 远程存储
    -......
    帮我写一个React 待办清单页面，支持新增，删除任务。
    还要：
    ```
    遵守胶水编程思维：优先使用成熟方案，避免凭空造逻辑。
    第一个阶段：只做规划,禁止输出任何代码。
    1.确认技术栈：
    React 19 + TailWindcss + useState
    2.梳理功能边界
    - 新增待办,删除待办,切换完成状态
    - 不做本地持久化,筛选,拖拽功能
    3.拆分模块（组件）
    输入框组件，待办条目组件，列表容器组件
    4.定义数据流
    useState 存储task数组 数据结构：{id，text，completed}
    5.输出这份完整规划，等待我确认无误后，再分段实现代码
    ```

    背后逻辑
    先划定边界：防止AI 自己多加功能，无限膨胀成屎山。
    强制模块拆分（好读好维护，AI生成代码我们都要审核），
    引导AI复用独立组件，预先规定数据结构，从根源减少AI 参数，字段幻觉（保证前后端传递的参数一致）
    先生成规划，审核规划，更新规划。
    这份规划将伴随我们的项目开发完整周期。


    第二个阶段："胶水"编程思维:
    能抄就不写（GitHub 经典的代码），能连不造（如果A,B,C组件能解决问题，那么就不自己写）
    指挥AI 去找那些已经被验证过千万次的成熟组件，把它组装起来。
    这样操作后产生幻觉和屎山的可能性大大降低。

    胶水本身不创造零件，只负责把现成零件粘在一起，你只负责写衔接，调用，流转的粘合代码，把各个模块联通。

## 举例
React 待办，连贯演示。
当前我们已经完成项目规划，现在正式写代码，对比两种方式：

- 错误
    从零造零件，高幻觉风险
    直接说 帮我写React待办清单的拖拽排序功能
    AI可能会凭空写一个，但是bug会很多，代码难以维护
    应该这样写:当前需求：给待办列表增加拖拽排序。
    1.先调研：React生态成熟的拖拽库，优先选用react-beautiful-dnd（业内广泛使用）
    2.不要手写拖拽代码，只做粘合工作。
    3.输出内容顺序：
    安装依赖命令，把现有TodoList组件合react-beautiful-dnd进行衔接。
    只写模块之间适配，数据流转的粘合代码

- 第三阶段 用元方法论让AI 自我进化
    可以不断帮我们优化提示词
    a（阿尔法）提示词 怎么干活
    欧米伽 提示词去根据生成结果，打分，判断，AI系统会不断进化
