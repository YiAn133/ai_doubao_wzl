# 任务拆分：[项目名称]

> 模板说明：本文档是 AI 开发的第三步，把需求拆成可独立完成、可验证的任务。**AI 严格按本文件执行**：一次一个任务，逐条对照验收标准。
> 填空占位符：【填写内容】。写完可删除本"模板说明"块。

## 1. 拆分原则

1. **按优先级分组**：P0（骨架）→ P1（核心能力）→ P2（主界面/集成）→ P3（辅助/增强）。
2. **独立可完成**：每个任务完成后都能看到明确效果，可单独验证。
3. **减少依赖**：任务间依赖尽量少，可并行的优先并行。
4. **明确关联页面/模块**：每个任务标注对应布局/模块，便于对照实现。
5. **实现说明精简**：只给关键约束，不给完整代码（防止 AI 与文档脱节）。

## 2. 任务总览

| 优先级 | 任务 | 对应页面/模块 | 依赖 |
| --- | --- | --- | --- |
| P0 | 任务1 【骨架/初始化】 | 【模块】 | 无 |
| P1 | 任务2 【核心能力 A】 | 【模块】 | 任务1 |
| P1 | 任务3 【核心能力 B】 | 【模块】 | 任务1 |
| P2 | 任务4 【主界面/集成】 | 【模块】 | 任务2、任务3 |
| P3 | 任务5 【辅助功能】 | 【模块】 | 任务4 |

> 可并行说明：任务2 与任务3 相互独立，可在任务1 后并行推进。

## 3. 任务详情

### 任务1：工程初始化与骨架（P0）

- **目标**：【搭好可运行的最小工程，加载/启动后能看到占位内容】
- **对应页面/模块**：【各入口，均为占位骨架】
- **依赖**：无。
- **完成标准**：【工程能跑起来，各入口可见，无报错】
- **主要产出**：
  - 【配置文件 1】
  - 【源码入口目录 1】
- **验收要点**：
  - 【如何手动验证：打开哪个入口，看到什么】
  - 【依赖安装完整：列出必须装齐的库】

### 任务2：【核心能力 A】（P1）

- **目标**：【一句话说明该能力产出什么】
- **对应页面/模块**：【数据来源/被谁使用，标注需求文档对应章节】
- **依赖**：任务1。
- **完成标准**：【给出具体输入输出。如：传入 X，返回含 A/B/C 字段的结构；字段缺失时如何兜底】
- **主要产出**：
  - 【文件列表】
- **验收要点**：
  - 【字段/格式是否完整】
  - 【边界处理是否生效（如缺失时兜底、异常时提示）】

### 任务3：【核心能力 B】（P1）

- **目标** / **依赖** / **完成标准** / **主要产出** / **验收要点**：结构同上。

### 任务4：【主界面 / 链路集成】（P2）

- **目标**：串联前面能力，形成用户可用闭环。
- **对应页面/模块**：布局示意图【页面名】的【模块清单】。
- **依赖**：任务2、任务3。
- **完成标准**：用户【操作 A】后，系统完成【A→B→C】；【操作 B】可【导出/保存】。
- **主要产出**：
  - 【UI 组件目录】
  - 【hooks/编排逻辑】
- **验收要点**：
  - 【输出格式严格遵循 proposal 定义的格式】
  - 【交互细节：加载态置灰 / 无结果时按钮禁用】
  - 【核心渲染组件正常】

### 任务5：【辅助功能】（P3）

- 结构同上，可写：设置面板、导出、持久化、入口等。

## 4. 依赖关系

```
任务1（骨架）
   ├── 任务2（能力A） ──┐
   └── 任务3（能力B） ──┤
                        ├── 任务4（主界面/集成）
                        │        └── 任务5（辅助）
```

- 任务2、任务3 无相互依赖，可并行。
- 任务5 在任务4 后推进。

## 5. AI 执行规则（强制）

1. 每次只执行一个明确指定的任务，**完成后等待用户确认**再做下一个。
2. 严格按任务范围执行，不得自行扩展；如需扩展先通知用户确认。
3. 任务完成后对照本节/对应任务的"验收要点"自检，并总结完成情况。
4. 任务描述不清晰时先询问，不自行决定。
