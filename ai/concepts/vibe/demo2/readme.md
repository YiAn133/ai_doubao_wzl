# Vibe Coding Harness工具

## Git
- 提交是git add . 然后再git common -m ’‘
- Head指针
指向当前文件所在的分支，所在的版本。
git reset --hard
git reset --soft
回退到历史的任意版本
-- hard 丢弃目前的修改，直奔那个版本，仓库是干净的
-- soft 保留文件内容，但是版本变为之前的版本，之前文件内容的提交，进入暂存区
git restore --staged 将暂存区的代码移除，文件内容不变
git checkout 丢掉当前文件夹的修改，回到之前的状态


## Vibe Coding 开发前的步骤和关键点

通过Vibe Coding，项目推进特别块，但是越到后面越是屎山代码，最后整个项目崩盘。

问题在哪里？
不在AI强还是不强。
问题在于vibe coding ，他不是说，把这个活直接丢给AI，就可以去喝咖啡了。
还有你构建一套工作流程，去驾驭AI。

## vibe Coding 标准工作流

### 开发前9个步骤
- 三个阶段
    - 第一个阶段叫定图纸。
        1. 先别去写代码，先去导需求。
        就像你和朋友聊天一样，把痛点（足够痛，无法解决），把目标用户，使用场景和你理想中的核心功能，全部
        告诉AI，不用追求严谨。
        2. 定完这个需求后，把这个需求整理成一个PRD文档，你来验收
        让AI输出一份结构化的文档，中间包括功能列表，用户流程，页面清单，每个功能你都要补上一句，到底做到
        什么程度才算完成？
        比如：登场成功，不是一句话，要说清楚，登录失败提示什么，登录成功以后跳转到哪里？
        3. 提前定好视觉和页面框架
        找2-3个参考网站，去让AI生成，目的是为了不让AI，一边写功能，一边把UI推导重来。
    - 第二个阶段打地基
        4. 明确项目边界和非功能需求
        本地跑？还是线上公开的？用户量多少？性能和成本有没有上限？
        安全，性能，可用性，成本，这四个非功能性需求不清楚，后面肯定会反工。
        5. 锁定技术栈
        6. 让AI出轻量架构草案。
        目录架构怎么分层
        核心模块有哪些？
        数据模型长什么样
        有哪些组件。
    - 第三阶段 立规矩
        7. 固化成文档
        现在的Agent 和 llm 交互都会用一个文档需要把PRD，设计，架构，当前状态写成项目根目录下的几个文本
        固化下来PRD.md（产品需求）  ARCH.md（系统架构文档）  Project.md（当前项目阶段） .....
        这些都是AI的全局上下文，vibe coding永久约束。
        8. 定开发规范和建参考资料文件夹
        - 代码规范
        - 错误处理
        9. 搞好git 和质量闸门
