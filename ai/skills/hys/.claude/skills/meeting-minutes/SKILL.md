# 会议纪要生成

这个技能帮助用户将原始的会议文字稿（如录音转写文本、速记笔记等）整理为一份结构清晰、重点突出的标准会议纪要。

## 工作流程

### 第一步：通读与清理

仔细阅读用户提供的全部文字内容，在此过程中：

1. **识别并去除填充词/停顿词** — 如"嗯"、"啊"、"那个"、"就是说"、"然后呢"、重复的口头禅等，这些不是会议内容，应予剔除
2. **识别并去除无关闲聊** — 会议前后与主题无关的寒暄、闲聊、跑题内容（但如果闲聊中包含了背景信息或参会者关系的线索，可以简要提取）
3. **修正明显的转写错误** — 如果是语音转文字的结果，结合上下文修正同音词、断句错误等（如"公鸡"→"供给"），但不确定的地方保留原文并标注 `[?]`
4. **保留所有实质性讨论内容** — 观点、分歧、决策、承诺、数据、时间节点等信息必须保留，宁多勿少

### 第二步：结构化输出

使用以下固定模板输出会议纪要。**模板中的每个字段都必须出现**，无法从文稿中确定的内容填写"（待确认）"或留空。

---

## 输出模板

输出时请严格按照以下结构，以 Markdown 格式呈现：

```markdown
# 会议纪要

## 一、会议基本信息

| 项目 | 内容 |
|------|------|
| 会议主题 | （填写） |
| 日期时间 | （填写，格式：YYYY年MM月DD日 HH:MM） |
| 会议地点 | （填写，线上会议注明平台） |
| 主持人 | （填写） |
| 记录人 | （填写） |
| 参会人员 | （填写，列出姓名及角色/部门） |
| 缺席人员 | （填写，无则写"无"） |

## 二、会议目标与背景

### 会议目的
（简要说明为什么要开这个会，期望达成什么结果）

### 背景信息
（相关的项目背景、前置讨论、外部因素等，帮助理解会议上下文）

### 预算/资源
（如果涉及预算讨论，在此说明；不确定则留空或写"未涉及"）

## 三、会议内容

### 主题一：（主题名称）

**讨论要点：**
- （要点1）
- （要点2）

**主要观点：**
- （发言人/角色）：（观点摘要）
- （发言人/角色）：（观点摘要）

**结论/决议：**
- （达成的共识或决定，无则写"未形成明确结论"）

### 主题二：（主题名称）

**讨论要点：**
- ...

**主要观点：**
- ...

**结论/决议：**
- ...

> 主题数量根据会议实际内容灵活增减。如果某个主题下有子议题，可用三级标题展开。

## 四、行动项

| 序号 | 行动内容 | 负责人 | 截止时间 | 备注 |
|------|----------|--------|----------|------|
| 1 | （具体可执行的任务描述） | （姓名） | YYYY-MM-DD | （依赖条件等） |
| 2 | ... | ... | ... | ... |

> 行动项必须包含：谁、在什么时间前、完成什么。如果文稿中只有模糊的"我们后面再弄"，将其提炼为具体的行动项，不确定负责人或时间时写"待确认"。

## 五、待确认事项

- （会议中提到但未明确的事项1）
- （事项2）

> 这一节汇总会议中提到但信息不完整或需要后续确认的内容。

## 六、附件/参考资料

- （会议中提到的文档、链接、PRD等，无则写"无"）
```

## 输出原则

1. **忠实于原文** — 不要编造会议中没有提到的内容。如果某个信息无法从文稿中确认，填写"（待确认）"或留空，不得臆测
2. **信息密度优先** — 去除冗余后，每个句子都应承载有用信息。不写"大家对这个问题进行了热烈的讨论"这类空泛描述，直接写讨论了什么
3. **区分事实与观点** — 当文稿中某人的发言是个人判断而非客观事实时，用"XX认为"、"据XX称"等表述予以区分
4. **保护敏感信息** — 如果文稿中包含手机号、身份证号等个人隐私信息，用 `***` 脱敏处理
5. **保持中立** — 作为记录者，不添加主观评价，不偏向任何一方的观点
6. **行动项可执行** — 每个行动项都应能被"完成"或"未完成"来判定。避免"关注一下"、"想想办法"这类模糊表述，尽量还原为具体任务
7. **原文与纪要对照** — 如果用户提供的内容信息非常丰富，可以在纪要末尾附上一句"如需查看完整讨论细节，请参考原始文稿"

## 示例

**输入文稿**（简化示例）：

```
嗯，那个，今天我们开个会啊，主要是讨论一下Q3的产品上线计划。
那个小李你说一下现在的进度吧。
嗯好的王总，我们目前后端已经开发完了，但是前端还差登录模块，预计下周五之前能搞定。
就是说还需要测试是吧？对，然后测试的话，小张你那边大概需要多久？
嗯我觉得至少得两周吧，因为这次改动挺大的。
行那就这样，小李下周五之前完成前端开发，小张你在小李交付后两周内完成测试。
好，另外就是预算的问题，大家可能也听说了，我们Q3的预算被砍了20%，这个后面再找财务确认一下具体的数字。
好，那就先这样，散会。
```

**输出纪要**：

```markdown
# 会议纪要

## 一、会议基本信息

| 项目 | 内容 |
|------|------|
| 会议主题 | Q3产品上线计划讨论 |
| 日期时间 | （待确认） |
| 会议地点 | （待确认） |
| 主持人 | 王总 |
| 记录人 | （待确认） |
| 参会人员 | 王总、小李（后端开发）、小张（测试） |
| 缺席人员 | 无 |

## 二、会议目标与背景

### 会议目的
对齐Q3产品上线进度，明确各模块交付时间节点

### 背景信息
（待确认）

### 预算/资源
Q3预算被削减20%，具体金额待与财务确认

## 三、会议内容

### 主题一：Q3产品上线进度对齐

**讨论要点：**
- 后端开发已基本完成
- 前端登录模块尚未完成
- 测试工作量和时间评估

**主要观点：**
- 小李：后端开发已完成，前端登录模块预计下周五前完成
- 小张：此次改动较大，测试至少需要两周时间

**结论/决议：**
- 前端开发截止时间为下周五（具体日期待确认）
- 测试周期为两周，在前端交付后启动

## 四、行动项

| 序号 | 行动内容 | 负责人 | 截止时间 | 备注 |
|------|----------|--------|----------|------|
| 1 | 完成前端登录模块开发 | 小李 | 下周五 | |
| 2 | 在前端交付后完成产品测试 | 小张 | 小李交付后两周内 | 依赖行动项1 |
| 3 | 与财务确认Q3预算被削减20%的具体金额 | （待确认） | （待确认） | |

## 五、待确认事项

- 会议的具体日期和时间
- 会议地点
- Q3预算被削减20%的具体金额及影响范围
- 与财务确认预算的责任人

## 六、附件/参考资料

- 无
```

## 注意事项

- 如果用户提供的是**录音文件**而非文字稿，先使用可用的语音转文字工具将录音转为文字，再执行上述流程
- 如果用户提供的文字稿非常长（超过5000字），可以先输出一份"摘要版"（控制在800字以内），再附上完整版
- 对于英文会议内容，用英文输出纪要，但模板结构保持一致
- 输出完成后，主动询问用户是否需要调整格式、补充信息或导出为其他格式（如 Word、PDF 等）
